# Grids and Graphs（網格與圖）：A* 如何理解遊戲地圖？

## 1. 為什麼要把地圖表示成 Graph？

Dijkstra’s Algorithm 與 A* 的輸入是 **Weighted Directed Graph（帶權重的有向圖）**。

簡化來說，圖由：

- **Nodes（節點）**：位置或狀態。
- **Edges（邊）**：節點之間可進行的連接。
- **Weights（權重）**：沿著邊移動所需的成本。

組成。遊戲地圖中的格子看起來不是圖，但可以視為圖的一種特殊形式：

```text
一張格線地圖                 同一張地圖的圖表示
+--+--+--+--+                A ---- B ---- C
|  |  |  |  |                |      |      |
+--+--+--+--+                D ---- E ---- F
|  |##|  |  |                |      X      |
+--+--+--+--+                G ---- H ---- I
```

其中 `##` 表示障礙格，圖表示中的 `X` 表示不可連接或不加入圖中的節點。

Graph Search 不需要理解圖面外觀；它只需要知道有哪些節點，以及哪些節點之間有邊。

## 2. Graph 的基本組成

一個數學圖至少需要兩項資訊：

1. **Set of nodes（節點集合）**：有哪些位置。
2. **Set of edges（邊集合）**：每個節點連到哪些節點。

節點也稱為 Vertex 或 Node；邊也稱為 Link、Connection、Arc 或 Arrow。

例如：

```text
節點：A、B、C、D
連接：A → B、A → C、B → D、C → D
```

用圖畫的位置不會改變圖本身。如果兩張圖用不同位置排列相同節點與相同連接，它們仍然是相同的 Graph。

這個特性對尋路很重要：A* 主要依靠節點連通性，不依靠圖表看起來是否左右顛倒。

## 3. Square Grid 的節點

對於矩形方格地圖，可以把座標 `(x, y)` 當作節點。

原始資料的 `20 × 10` 範例可以用以下方式建立所有節點：

```python
all_nodes = []

for x in range(20):
    for y in range(10):
        all_nodes.append([x, y])
```

簡化的 `3 × 3` 地圖可以表示為：

```text
(0,0) (1,0) (2,0)
(0,1) (1,1) (2,1)
(0,2) (1,2) (2,2)
```

格線地圖的座標、大小與位置可提供額外資訊，但最基本的 Graph Search 只需要節點及相鄰連接。

## 4. Neighbors：找出相鄰節點

每個節點都需要知道哪些節點是 **Neighbors（鄰居）**。

### 4.1 四方向移動

若角色只能向東、北、西、南移動，方向列表為：

```python
dirs = [[1, 0], [0, 1], [-1, 0], [0, -1]]
```

原始資料的 neighbors 函式概念是：

```python
def neighbors(node):
    dirs = [[1, 0], [0, 1], [-1, 0], [0, -1]]
    result = []

    for direction in dirs:
        neighbor = [
            node[0] + direction[0],
            node[1] + direction[1]
        ]
        result.append(neighbor)

    return result
```

實際尋路時不能加入地圖外或障礙格。原始資料提供兩種矩形地圖檢查方式：

```python
# 檢查節點是否存在於可走節點集合
if neighbor in all_nodes:
    result.append(neighbor)
```

```python
# 直接檢查座標是否在矩形範圍內
if 0 <= neighbor[0] < 20 and 0 <= neighbor[1] < 10:
    result.append(neighbor)
```

第一種方式適合節點集合會變動的地圖；第二種方式只適合矩形地圖範圍固定的情況。

### 4.2 八方向移動

若遊戲允許對角移動，方向列表要增加對角方向，因此 `dirs` 會有八個項目。

原始資料只說明「八方向可用八個 entries」，沒有提供完整的對角移動程式碼。因此本文不自行假設特定對角成本或斜角穿越規則。

在實際遊戲中，對角移動是否允許穿過角落障礙、對角成本是否為斜邊距離，都需要另外依遊戲規則實作。

## 5. Undirected Graph

**Undirected Graph（無向圖）** 的邊可以雙向通行。

例如：

```text
B ↔ C
```

表示同時存在：

```text
B → C
C → B
```

大多數一般遊戲地圖都是無向圖：只要沒有特殊限制，從相鄰格子可以雙向移動。

在 Graph 資料結構中，每個無向邊可能會被列出兩次，一次是從節點出發，一次是從相反節點出發。

## 6. Directed Graph

**Directed Graph（有向圖）** 的邊只允許特定方向移動。

例如：

```text
B → C
```

不一定存在：

```text
C → B
```

原始資料列出的例子包括：

- 單向門。
- 從平台跳下後不能直接跳回原平台。
- 單向傳送門。

在有向圖中，`neighbors(node)` 必須只回傳該節點目前可走出的方向。

## 7. Multigraph

**Multigraph（多重圖）**允許兩個相同節點之間存在多條邊。

例如，角色可從節點 `B` 到節點 `C`：

- 游泳穿越河流。
- 搭乘木筏穿越河流。

這兩種方式可以是兩條不同的邊，雖然起點與終點相同，但成本或限制可能不同。

一般簡單的格線尋路較常使用每個節點對鄰居各一條邊；只有需要區分多種移動方式時，才需要 Multigraph 概念。

## 8. Weighted Graph

**Weighted Graph（加權圖）**會在每條邊上附加數值權重，也就是移動成本。

原始資料的例子：

- 無向圖：鋪好的道路權重為 `1`；彎曲的森林道路權重為 `4`。
- 有向圖：下坡邊的權重為 `2`；上坡反向邊的權重為 `5`。

Weighted Graph 對尋路演算法很重要：

- 最短路徑不一定是移動格數最少的路徑。
- Dijkstra 或 A* 需要將 Edge Cost 納入計算。
- 權重較低的道路可能比通過較少格子的道路更容易通行。

在前一篇 A* 文章中的 `cost_so_far` 與 `graph.cost(current, next)`，就是在使用這種邊權重。

## 9. 障礙物如何表示？

原始資料提出三種一般策略。

### 9.1 Remove Nodes：移除節點

障礙物佔據格子時，可以把障礙格從節點集合移除。

例如：

```text
. . # .
. . # .
. . . .
```

障礙格 `#` 不應出現在 `all_nodes`。

使用：

```python
if neighbor in all_nodes:
    return neighbor
```

時，通往障礙格的邊也會因目標節點不存在而不被加入。

### 9.2 Remove Edges：移除邊

障礙物可能位於格線邊界，而不是格子本身。

此時可以在 `neighbors()` 中加入額外檢查，阻止角色穿過不可通行的邊。

例如，如果障礙物是牆壁，節點仍然存在，但牆壁兩側之間沒有邊。

### 9.3 Infinite Weight：無限權重

障礙邊或通往障礙格的邊可以標記為 `Infinity`。

Graph Search 在取得無限成本邊時，應在繼續探索前停止處理該節點或將其視為不可到達。

這種方法對動態修改障礙物較方便：只需改變邊權重，不一定要重建整個節點集合。

## 10. Grid 與一般 Graph 的關係

Grid 是 Graph 的特殊情況，因為它會額外知道座標與規則化的鄰居位置。

一般 Graph Search 只需要：

- 節點集合。
- 範圍內的鄰居或邊。
- 每條邊的權重。

但使用 Grid 的額外特性時，演算法可能可以比一般 A* 更快。原始資料也提示，這不是一般 Graph Search 必須知道的座標與版面資訊。

對初學者而言，將 Grid 轉成 Graph 有一個簡單順序：

1. 每個可走格子建立節點。
2. 每個相鄰可走格子建立邊。
3. 設定邊權重。
4. 移除障礙節點或障礙邊。
5. 輸入 Dijkstra 或 A*。

## 11. 這些概念如何連到 A*？

A* 的實際工作可以分成：

```text
地圖
  -> 選擇哪些格子是節點
  -> 找出四方向或八方向鄰居
  -> 移除障礙或設定無限權重
  -> 建立 Directed / Undirected、Weighted Graph
  -> 交給 Dijkstra 或 A* 搜尋
  -> 重建路徑
```

Graph 的連通性決定演算法可能走哪些位置。

Edge Weight 決定哪條路較便宜。

Heuristic 決定 A* 優先探索哪些節點。

因此：

- Node 決定「可以在何處」。
- Edge 決定「可以怎麼移動」。
- Weight 決定「移動多少成本」。
- Neighbor 決定「下一步有哪些選擇」。
- A* 決定「依據成本與估計距離選擇哪條路」。

## 12. 初學者實作建議

建立第一個 Grid-to-Graph 範例時：

1. 先建立矩形座標節點。
2. 先用四方向移動，不要一開始加入對角。
3. 用座標範圍檢查排除地圖外的節點。
4. 用障礙集合排除不可走格子。
5. 每條可走邊先設定權重 `1`。
6. 再加入不同地形成本。
7. 將鄰居資料交給 BFS、Dijkstra 或 A*。

只要先確定節點與邊，就能替換不同尋路演算法，而不必每次重寫整張地圖。
